# DaikonDB

Легковесная встраиваемая key-value СУБД с интерфейсом, совместимым с подмножеством команд Valkey. Проект реализован как индивидуальная работа по изучению архитектуры in-memory хранилищ и современных возможностей C++20

## Описание

DaikonDB - это однопоточная in-memory база данных, встраиваемая в процесс приложения. Она предоставляет текстовый интерфейс командной строки: команды читаются из стандартного ввода, результаты выводятся в стандартный вывод. Синтаксис команд следует спецификации Valkey (Redis), что упрощает интеграцию и тестирование

## Архитектура

Проект построен по модульному принципу с четким разделением ответственности:

- **Ядро хранилища (`core::DBase`)** - управляет таблицей ключ-значение, отвечает за выделение памяти через кастомный аллокатор с трекингом, реализует механизм TTL и фоновое удаление просроченных записей
- **Типы данных** - иерархия объектов (`BaseDataObject`), включающая строки, списки, множества и геопространственные индексы
- **Слой команд (`DaikonDatabase`)** - фасад, принимающий текстовые команды, валидирующий аргументы и преобразующий их в вызовы к ядру. Возвращает типизированные результаты через `std::expected`
- **Геопространственный индекс** - собственная реализация квадродерева (`Quadtree`) с поддержкой разбиения узлов, поиска в радиусе и учета антимеридиана
- **Система памяти** - кастомный аллокатор `TrackingAllocator` и `MemoryTracker` обеспечивают точный (с точностью до накладных расходов) учет потребляемой ОЗУ на уровне каждого объекта

## Реализованные типы данных и команды

### String

| Команда | Описание |
|---------|----------|
| `SET key value` | Установить строковое значение ключа |
| `GET key` | Получить значение ключа |
| `STRLEN key` | Длина строки |
| `APPEND key value` | Добавить строку к существующему значению |

### List

| Команда | Описание |
|---------|----------|
| `LPUSH key value [value ...]` | Добавить элементы в начало списка |
| `RPUSH key value [value ...]` | Добавить элементы в конец списка |
| `LPOP key [count]` | Извлечь элементы из начала |
| `RPOP key [count]` | Извлечь элементы из конца |
| `LLEN key` | Длина списка |
| `LRANGE key start stop` | Подсписок по индексам, включая отрицательные |
| `LINDEX key index` | Элемент по индексу |
| `LSET key index value` | Установить элемент по индексу |
| `LINSERT key BEFORE\|AFTER pivot value` | Вставить элемент до или после опорного |

### Set

| Команда | Описание |
|---------|----------|
| `SADD key member [member ...]` | Добавить элементы во множество |
| `SREM key member [member ...]` | Удалить элементы |
| `SISMEMBER key member` | Проверить принадлежность |
| `SMEMBERS key` | Все элементы множества |
| `SCARD key` | Мощность множества |
| `SUNION key [key ...]` | Объединение множеств |
| `SINTER key [key ...]` | Пересечение множеств |
| `SDIFF key [key ...]` | Разность множеств |
| `SMOVE source destination member` | Переместить элемент между множествами |

### Geospatial

| Команда | Описание |
|---------|----------|
| `GEOADD key lon lat member [...]` | Добавить точки с координатами |
| `GEOPOS key member [member ...]` | Получить координаты |
| `GEODIST key m1 m2 [unit]` | Расстояние между точками (m, km, mi, ft) |
| `GEOSEARCH key FROMLONLAT lon lat BYRADIUS r unit [ASC\|DESC] [COUNT n]` | Поиск точек в радиусе |
| `GEOSEARCHSTORE dest source FROMLONLAT lon lat BYRADIUS r unit [ASC\|DESC] [COUNT n]` | Сохранить результат поиска в ключ |

Расстояние вычисляется по формуле Хаверсина с радиусом Земли 6372.8 км. Для индексации используется квадродерево с адаптивным разбиением узлов.

### Общие команды

| Команда | Описание |
|---------|----------|
| `TYPE key` | Тип значения ключа (string, list, set, zset, hash, none) |
| `DEL key [key ...]` | Удалить ключи |
| `EXISTS key [key ...]` | Проверить существование ключей |
| `KEYS pattern` | Поиск ключей по шаблону |
| `FLUSHDB` | Удалить все ключи |
| `CONFIG SET maxmemory <bytes>` | Установить лимит памяти |
| `CONFIG GET maxmemory` | Получить текущий лимит памяти |
| `DBSIZE` | Количество ключей |
| `MEMORY USAGE key` | Оценка памяти, занимаемой ключом |
| `EXPIRE key seconds` | Установить TTL в секундах |
| `TTL key` | Оставшееся время жизни |

## Особенности реализации

### Управление памятью

Все структуры данных используют единый кастомный аллокатор с трекингом. Это позволяет:
- отслеживать суммарное потребление ОЗУ в реальном времени
- ограничивать память через аргумент `--maxmemory` (поддерживаются суффиксы b, kb, mb, gb) или команду `CONFIG SET`
- возвращать ошибку `(error) OOM command not allowed when used memory > 'maxmemory'` при исчерпании лимита

### TTL и истечение ключей

Каждый ключ может иметь время жизни. Протухшие записи удаляются при обращении (lazy expiration) и фоновом проходе по упорядоченной очереди истечений (expire queue)

### Обработка ошибок

Вместо исключений внутренняя логика использует `std::expected<T, LogicError>` из C++23 (или совместимую реализацию). Это позволяет явно моделировать ошибки домена: неверный тип, отсутствие ключа, nil, нехватка памяти

### Геопространственный индекс

Реализовано собственное квадродерево с поддержкой:
- адаптивного разбиения по количеству точек и глубине
- поиска в радиусе с корректной обработкой антимеридиана
- сортировки результатов по расстоянию и ограничения выдачи (COUNT)

## Технический стек

- **Язык:** C++20
- **Ключевые конструкции:** concepts, `std::expected`, `std::string_view`, шаблоны с SFINAE
- **Структуры данных:** `std::unordered_map`, `std::set`, `std::vector` с кастомными аллокаторами
- **Алгоритмы:** Хаверсин, квадродерево
- **Тестирование:** собственный набор модульных тестов

## Сборка

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

## Использование

### Интерактивный режим

```bash
./app.exe --maxmemory 64mb
```

Команды вводятся построчно. Названия команд нечувствительны к регистру, ключи - чувствительны. Для завершения введите `EXIT` или закройте поток ввода

### Примеры

```
SET user:1 "Alice"
GET user:1
LPUSH queue job1 job2 job3
LLEN queue
GEOADD cities 37.6176 55.7558 Moscow 30.3086 59.9375 SPb
GEOSEARCH cities FROMLONLAT 37.6176 55.7558 BYRADIUS 500 km ASC
```

## Тестирование

Проект включает набор модульных тестов, покрывающих:
- базовые операции со строками, списками и множествами
- геопространственные запросы и точность вычислений расстояний
- механизм TTL и истечения ключей
- контроль памяти и поведение при достижении лимита
- обработку ошибок (неверный тип, отсутствие ключа)

Запуск тестов:

```bash
ctest --output-on-failure
```
